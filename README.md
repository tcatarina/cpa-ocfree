# CPA plugin: OpenCode Free

A [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) plugin that serves the
keyless free models on [OpenCode Zen](https://opencode.ai/zen) through an ordinary
`openai-compatibility` provider.

The free tier answers `403` unless a request carries a specific client contract.
This plugin applies the part that belongs in the request body, and ships a
generated provider block for the part that CPA applies itself.

## What it does

| Contract part | Handled by |
|---|---|
| `stream: true` forced upstream | plugin (request interceptor) |
| non-empty `tools` with names the tier accepts | plugin (request interceptor) |
| `User-Agent: opencode/1.17+` | provider `headers:` |
| `x-opencode-session` / `x-opencode-request` | provider `headers:` |
| `x-opencode-project` / `x-opencode-client` | provider `headers:` |
| JSON reply for a caller that asked for one | plugin (response interceptor) |

Only the identity headers are routed through the provider block because CPA's
`openai-compatibility` executor sets `User-Agent` itself and does not forward
interceptor headers upstream. The provider block is generated by the plugin so
the two halves cannot drift.

## Install

1. Drop `ocfree.so` into `<plugins-dir>/<os>/<arch>/`
2. Enable it in `config.yaml`:

   ```yaml
   plugins:
     enabled: true
     dir: "/path/to/plugins"
     configs:
       ocfree:
         enabled: true
   ```

3. Add the provider block. With the panel open, the **OpenCode Free** page
   serves it at `?asset=provider`, or:

   ```bash
   curl -s -H "Authorization: Bearer $CPA_MANAGEMENT_KEY" \
     http://127.0.0.1:8317/v0/resource/plugins/ocfree/ocfree?asset=provider
   ```

4. Restart CPA. The catalog only refreshes on a real config change or restart.

## The generated provider block

```yaml
openai-compatibility:
  - name: opencode-free
    base-url: https://opencode.ai/zen/v1
    # An empty key sends no Authorization header. A non-empty one is
    # rejected upstream with 401 Invalid API key.
    api-key-entries:
      - api-key: ""
      - api-key: ""
      - api-key: ""
    headers:
      User-Agent: "opencode/1.18.31"
      x-opencode-session: "ses_..."
      x-opencode-request: "msg_..."
      x-opencode-project: "global"
      x-opencode-client: "desktop"
    models:
      - name: space-bunny-free
```

Two details are load-bearing:

- **The API keys must be empty.** A populated key is sent as
  `Authorization: Bearer <key>` and the upstream answers
  `401 Invalid API key`. Empty keys still yield one auth record per entry,
  because the stable id generator suffixes duplicates, so three entries give
  rotation three independent members with their own cooldowns.
- **The session id must be canonical**: `ses_` + 12 hex + 14 base62, 26
  characters. The tier checks the shape, not the value. A malformed id is
  refused with `FreeTierError`.

## Models

Measured 2026-09-29 against the live endpoint. The `-free` suffix alone is not a
reliable filter: of eleven `-free` models, four were unserved, and `big-pickle`
works with no suffix at all. The plugin ships an explicit allowlist.

| model | verified |
|---|---|
| `big-pickle` | yes |
| `longcat-2.5-preview-free` | yes |
| `mimo-v2.5-free` | yes |
| `mimo-v2.6-flash-free` | yes |
| `nemotron-3-ultra-free` | yes, occasionally empty (budget spent on reasoning) |
| `nemotron-3.5-lightning-free` | yes |
| `space-bunny-free` | yes |

Also unserved at the time of writing: `deepseek-v4-flash-free` (`Model is
unavailable`), `jev-1.13-free`, `ling-3.0-flash-fin-free`, and both
`muse-spark-*-contributor-free` models. Edit the list on the plugin page when
the upstream catalogue changes; no rebuild is needed.

## Tools

The tier inspects the `tools` array, and acceptance varies by model: an invented
tool name is refused by most of them and accepted by `space-bunny-free`. The
plugin seeds the tool names the official client declares when a caller sends
none, and **appends** any missing ones when a caller sends its own set. A
caller's tools are never replaced, because the reply would then name a tool the
caller cannot dispatch. The injected tools are written in the caller's protocol
shape, since the body is still in that protocol when the interceptor runs.

Per-model tool names are configurable if acceptance shifts again.

## Protocol support

All four client surfaces work; CPA performs the translation:

| client | non-stream | stream |
|---|---|---|
| `/v1/chat/completions` | yes | yes |
| `/v1/messages` | yes | yes |
| `/v1/responses` | yes | yes |
| `/v1beta/...:streamGenerateContent` | yes | yes |

Because the contract forces `stream: true` upstream, a caller that asked for
JSON would otherwise receive an event stream. The plugin records the caller's
intent on the way in and folds the stream back into a single `chat.completion`
on the way out.

A mid-stream upstream error is surfaced rather than folded: a `503` that arrives
as a `data:` event becomes an `error` body instead of an empty completion. The
HTTP status stays `200`, because the response interceptor cannot set one.

## Configuration

The plugin block is `plugins.configs.ocfree`. Everything else is editable from
the panel, which round-trips YAML:

| key | meaning |
|---|---|
| `enabled` | apply the contract |
| `models` | the allowlist; requests for anything else pass through untouched |
| `tool_names` | names seeded when a caller sends no tools |
| `tools` | per-model override of `tool_names` |
| `user_agent` | must satisfy `opencode/1.17` or newer |
| `session_salt` | salt for the deterministic per-conversation session id |
| `upstream` | provider base URL |

## Build

```bash
make            # build and verify the exported C ABI symbol
make test       # unit tests
```

The binary must export `cliproxy_plugin_init`; the release workflow fails the
build if it does not, and also fails if the version was not stamped from the tag.

## Notes

The free tier and its contract are reverse-engineered from observed behaviour,
not from published documentation, and the upstream rotates both the catalogue
and its per-model tool acceptance. Treat the model list as something to check
rather than something to trust.
